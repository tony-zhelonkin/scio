# Reorient

Explain the endeavour's current state through its purpose, evidence and design decisions.

Scope: $ARGUMENTS

If no scope is supplied, use the active endeavour.

Read the relevant project instructions, scientific framing, current handoff, plans
and decision records. Check consequential claims against actual code, artifacts
and validation evidence. Verify live jobs if relevant. Distinguish historical
records from current observations.

Build a connected narrative in this order:

1. **Purpose and first principles.** What question are we trying to answer?
   What would success look like? Explain the basic biological or technical
   building blocks, what we actually measure, and the assumptions connecting
   measurements to claims.

2. **Why the design has this shape.** Explain the concrete pain points,
   constraints, bugs and surprises. Show how each consequential problem led
   to a design choice. Map the logical components to the actual code, inputs,
   transformations and outputs. Explain what downstream question each output
   supports.

3. **Decisions and tradeoffs.** For each consequential architectural decision
   record (ADR), state: premise → problem → alternatives → chosen approach →
   evidence → tradeoffs and caveats → downstream implications. Distinguish
   approved decisions, provisional choices, superseded choices and open
   questions. Identify agent recommendations separately from user approvals.

4. **Current standing.** What is implemented, executed, validated and
   biologically interpretable? What changed since our last discussion?
   What remains incomplete, uncertain, blocked or running? Distinguish
   successful execution from scientific acceptance, and reproducibility
   from correctness.

5. **What we learned and what comes next.** Explain what implementation taught
   us about the system being studied. Assess whether the present architecture
   still fits the question. Identify the next bounded milestone and longer-term
   path. For open decisions, explain the options, your recommendation and the
   evidence that would change it. State whether we are ready to visualize and
   interpret results, and what is still needed.

Start simply and add detail progressively. Explain the causal reasoning that
connects the components. Use concrete examples and a small diagram or decision
table where helpful. Link key evidence. Make uncertainty and unresolved
disagreements visible. Scale the report to the endeavour's complexity.

This command requests orientation and discussion. Perform read-only checks;
launch analyses, refactor, clean up or change scientific policy only when
separately instructed. Report unavailable evidence explicitly.
